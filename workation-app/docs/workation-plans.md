# 예약 없는 워케이션 업무 관리

직원과 HR은 `/workation-plans`를 사용합니다. 헤더와 직원 시작 화면에서 진입합니다.

## 적용

1. 기존 회사 연결 마이그레이션 `20260908_company_isolation.sql` 적용 상태를 확인합니다.
2. Supabase SQL Editor에서 `supabase/migrations/20260921_workation_plans.sql`을 한 번 실행합니다.
3. 서버의 기존 `SUPABASE_SERVICE_ROLE_KEY`와 Supabase URL 설정을 사용하여 앱을 배포합니다.
4. 서로 다른 회사의 HR 및 직원 계정으로 아래 흐름과 접근 차단을 확인합니다.

이번 변경은 기존 예약·목표·리포트를 자동 이관하지 않습니다. 새 워케이션은 예약 없이 독립적으로 저장합니다. 마이그레이션 미적용 시 준비 중 안내가 표시됩니다.

## 사용 흐름

- 직원: 워케이션 만들기 → 필수 계획·목표 입력 → 저장 → 목표 승인 요청.
- HR: 목록의 담당자 검토 대기 → 참가·목표 승인 또는 의견과 함께 수정 요청.
- 직원: 승인 후 누적 시간·진행률·업무 기록 저장 → 목표별 결과 설명과 선택 링크 제출.
- HR: 검토 완료 또는 보완 요청 → 직원 재제출 → 검토 완료.

수정·보완 의견은 필수입니다. 승인된 목표 내용은 업무 기록 시 변경할 수 없습니다. 결과 검토 완료는 모든 목표의 달성률 100%와 다릅니다. 미완료 사유를 포함한 결과도 제출할 수 있습니다.

## 접근 및 동시성

모든 API 요청은 실제 인증 토큰과 users 테이블의 승인 상태·회사·역할을 검사합니다. 직원은 자신의 기록만, HR은 같은 회사의 기록만 조회합니다. 역할과 상태에 맞지 않는 변경을 거절합니다. 테이블은 RLS를 활성화하고 클라이언트 직접 접근을 차단하며 서버 API에서만 접근합니다. version 비교와 조건부 갱신으로 동시 수정 유실을 막습니다.

## 이번 구현 범위 및 후속 작업

이번 구현: 독립 일정, 다중 목표, 저장·제출·승인·수정, 누적 시간·진행률·텍스트 기록, 결과 링크, 결과 검토·보완, 처리 이력, 예상·실제 시간 요약.

후속 개발: 승인 후 목표 변경 요청, 날짜별 업무 로그, 목표별 개별 평가, 제출 시점 기반 기한 준수 집계, 알림 발송, 파일 업로드 연결, 설문, 취소·종료 정책, 목록 페이지 분할.

현재 저장은 명시적 버튼 방식이며 자동 저장이 아닙니다. 화면 이동·새로고침 시 미저장 안내를 제공합니다. 이력에는 행동·담당자·시각·검토 의견을 남기며 수정 전후 전체 내용의 스냅샷은 아직 없습니다. 실서비스 전 데이터 보관 정책과 파일럿 규모에 따른 목록 제한을 검토합니다.

## 검증

`node --test tests/workation-plans.test.cjs`는 서버 인증, 회사 분리, 소유권, 상태 전환, 입력 검증, 동시 갱신 충돌을 검증합니다. 실제 Supabase 및 실제 계정 검증은 마이그레이션 적용 후 별도로 필요합니다.

## 연결 상태와 개발용 미리보기

2026-09-30 기준 개발 Supabase에 workation_plans 테이블을 적용하고 RLS 및 클라이언트 직접 접근 차단을 확인했습니다. 로컬 .env.local에 서버 연결을 설정했고, 앱의 Supabase 클라이언트로 users·companies·workation_plans 조회가 모두 HTTP 200으로 성공했습니다. .env.local은 Git에서 제외됩니다.

실제 직원·HR 로그인 상태의 제출·수정·승인 및 재로그인 후 저장 유지 검증은 미완료입니다. 배포 환경의 서버 키 설정과 운영 배포 확인도 별도로 필요합니다. 로컬 설정 파일은 푸시로 배포 환경에 전달되지 않습니다.

개발 서버의 `/workation-preview`에서는 예시 데이터로 직원·담당자 흐름을 체험할 수 있습니다. 새로고침하면 초기화되며 production 환경에서는 제공하지 않습니다. 실제 화면은 `/workation-plans`입니다.

제출 전 작성 중인 초안은 직원 본인에게만 보입니다. HR의 목록 조회 및 개별 처리에서 초안을 제외합니다. 제출 후에는 같은 회사의 담당자가 검토할 수 있습니다.

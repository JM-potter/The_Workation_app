# 직원 가입 승인

## 사용 순서
1. 플랫폼에서 승인된 인사담당자의 회사가 직원 가입 화면의 회사 목록에 표시됨.
2. 직원이 회사 목록에서 소속 회사를 선택하고 가입함. 이메일 인증을 요청받으면 인증 후 로그인함.
3. 인사담당자는 대시보드의 ‘직원 가입 승인’에서 신청자의 소속을 확인하고 승인함.
4. 직원은 대기 화면의 ‘승인 상태 다시 확인’을 누르거나 다시 로그인함.

## 운영 전제
- 서버에 SUPABASE_SERVICE_ROLE_KEY가 설정되어 있어야 함. 브라우저 환경변수로 노출하면 안 됨.
- 기존 가입 트리거가 public.users에 id, name, email, role, status, company_name을 저장해야 함. 프로필이 없으면 상태 조회는 409를 반환하며 자동 권한 부여를 하지 않음.
- 기존 스키마에 맞춰 company_name의 정확한 일치로 회사를 연결함. 동일 이름의 별도 회사 구분은 지원하지 않음. 향후 고유 회사 ID 필요.
- 로그인 가능 여부와 인사담당자 승인 여부는 별개임. The Workation 회사가 목록에 없다면 해당 HR의 실제 users.status와 company_name을 운영자가 확인해야 함.

## 검증과 한계
- node --test tests/employee-approval.test.cjs: 모의 DB로 인증 실패, 승인 전 HR/직원 접근 차단, 다른 회사 및 HR 승인 차단, 승인 저장 및 반복 요청, 회사별 목록, 잘못된 ID 검증.
- Next.js production build 및 타입 검사 통과.
- 실제 운영 계정의 승인 또는 개인정보 조회는 수행하지 않음. 운영 DB의 가입 트리거와 RLS는 확인하지 못했음.
- 신규 HR API는 서버에서 로그인 토큰과 DB의 역할/승인/회사를 검증함. 클라이언트 화면 이동 제한은 데이터 접근 통제를 대체하지 않음.
- 기존 /api/superadmin/*에는 호출자 인증이 없는 관리 경로가 남아 있음. 이번 직원 승인 기능과 별개로 관리자 인증을 보강해야 하며, 서비스 전체의 승인 우회 방지가 완료됐다고 볼 수 없음. DB에서도 일반 사용자가 role/status/company_name을 임의 수정하지 못하도록 권한을 확인해야 함.
